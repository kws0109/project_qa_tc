# 게임 컨텐츠 QA 인터뷰

사용자에게 게임 컨텐츠를 물어 지식 슬롯을 채우고, 채워진 슬롯에서만 테스트케이스를
만든다. **어떤 TC를 만들 수 있는지는 당신이 아니라 `qatc tc plan` 이 정한다.**

## 절대 규칙

1. **질문하기 전에 항상 `qatc slot status <컨텐츠> --json` 을 실행한다.**
   기억에 의존하지 않는다. 컨텍스트가 압축돼도 이 출력이 진실이다.
2. `open` 배열에 없는 항목은 **절대 다시 묻지 않는다.**
3. 한 번에 **1~2개만** 묻는다. 여러 개를 나열하면 인터뷰가 아니라 설문지가 된다.
4. 사용자가 "모른다"고 하면 `--status unknown`, "해당 없음"이면 `--status na` 로
   닫는다. 캐묻지 않는다. 잘못 기록했거나 사용자가 답을 되돌리면
   `--status empty` 로 되돌린다 — 그 항목이 다시 `open` 배열에 올라온다.
5. 답변이 모호하면 다음 항목으로 넘어가지 말고 그 자리에서 되묻는다.
6. 한 답변에 여러 항목의 정보가 있으면 `slot set` 을 **여러 번** 실행한다.

## 1단계 — 개괄 (항상 여기서 시작)

컨텐츠 이름을 받으면 **가장 먼저** (규칙 1대로) 상태를 확인한다:

```bash
.venv/Scripts/qatc.exe slot status <컨텐츠> --json
```

**`<게임>` 은 미리 묻지 않는다.** 지식 DB는 게임 단위(`knowledge/<게임>.db`)로
나뉘지만, `qatc config --game <게임>` 으로 정해 둔 **기본 게임**이 있으면
`slot init` 이 `--game` 없이도 그 게임을 쓴다. 이미 진행 중인 컨텐츠는
`--game` 없이도 CLI가 찾아내므로 (읽기 명령은 컨텐츠 이름으로 게임을
역추적한다) 신규 여부와 무관하게 묻지 않아도 된다.

**묻는 지점은 두 곳이고, 둘 다 CLI가 먼저 말해 준다.** (1) 아래 (b) 분기 —
같은 이름의 컨텐츠가 두 게임에 있을 때. **기본 게임은 이 경우를 해소하지 못한다**
(읽기 명령은 기본 게임을 쓰지 않는다). (2) 아래 "답을 들은 뒤" 절 — CLI가 게임을
알 수 없다고 답할 때(기본 게임이 없다는 뜻이다). 그 전에 먼저 묻지 않는다.

**`--game` 오타는 CLI가 거부한다 — 잘못된 이름으로 새 DB가 생기지 않는다.**
막는 방식은 명령에 따라 다르다:
생성 명령(`slot init` · `knowledge` · `config --game`)은 `profiles/` 와 대조하고,
읽기 명령은 대조하지 않는 대신 그 이름의 DB 파일이 없으면 만들지 않고 멈춘다
(읽기까지 대조하면 게임이 `profiles/` 를 떠났을 때 그 DB에 쌓인 인터뷰에
접근할 수 없게 된다).

출력에 따라 갈라진다:

- **아래 셋 중 하나가 나오면 → 신규 컨텐츠다.** 게임 이름을 확보하고,
  **`slot init` 은 아직 실행하지 말고** 곧장 아래 개괄 질문으로 시작한다.

  ```
  오류: 지식 DB가 없습니다. 먼저 'qatc slot init <컨텐츠> --game <게임>'을 실행하세요.
  오류: '<컨텐츠>' 컨텐츠를 가진 게임 DB가 없습니다. --game 으로 지정하세요.
  컨텐츠 '<컨텐츠>'가 없습니다. 'qatc slot init'을 먼저 실행하세요.
  ```

  두 번째 문구는 `--game` 을 지정하라고 하지만, **`--game` 을 붙여 다시 불러도
  세 번째 문구가 나올 뿐이다** — 어느 게임 DB에도 그 컨텐츠가 없다는 뜻이다.
  다시 불러 보느라 턴을 버리지 않는다. 세 문구 모두 `slot init` 을 먼저 하라고
  말하지만, 그 실행은 **개괄 답변을 들은 뒤**다 (이유는 아래 "왜 개괄이 먼저인가").

- **`오류: '<컨텐츠>'가 여러 게임에 있습니다 (...)` 가 나오면** → 괄호 안에
  나열된 게임 중 어느 것인지 사용자에게 묻고 `--game` 을 붙여 다시 부른다.
- **`open` 배열에 `overview` 가 있으면** (이미 만들어졌지만 아직 개괄을 안 받은
  컨텐츠) → 개괄 질문으로 시작한다. 컨텐츠는 이미 있으므로 다시 만들 필요는
  없지만, 답에서 새 유형이 드러나면 `slot init --types` 를 다시 실행해 그 유형의
  슬롯을 덧붙인다 (기존 값과 상태는 보존된다).
- **그 외 (`overview` 가 이미 닫혀 있으면)** → 개괄 질문을 건너뛰고 곧장
  2단계로 가서 `open` 배열의 남은 항목부터 묻는다. 규칙 2에 따라 이미 닫힌
  개괄을 다시 묻지 않는다.

### 개괄 질문

개괄 질문이 필요하면 이 문구로 시작한다:

```
[<컨텐츠>] 인터뷰를 시작합니다.

먼저 이 컨텐츠가 어떤 것인지 설명해주세요.
플레이어가 무엇을 하는 곳이고, 왜 쓰는지 편하게 적으시면 됩니다.
```

### 답을 들은 뒤 — 유형 판정과 `slot init`

답변에서 유형을 판정한다. 사용 가능한 유형: `가챠` `편성` `성장` `던전` `상점` `임무`.
복수 적용할 수 있다 (워프는 `가챠,상점`). 해당 없으면 `--types` 를 생략한다.

**`--game` 은 먼저 생략하고 시도한다.** `qatc config --game` 으로 정해 둔 기본
게임이 있으면 그대로 성공한다.

```bash
.venv/Scripts/qatc.exe slot init <컨텐츠> --types 편성
```

다음 오류가 나올 때만 사용자에게 묻는다(기본 게임이 없다는 뜻이다) —
"어느 게임의 컨텐츠인가요? (예: starrail, genshin)":

```
오류: 어느 게임인지 알 수 없습니다. --game <게임> 을 주거나, 'qatc config --game <게임>' 으로 기본 게임을 정하세요.
```

답을 들으면 `--game` 을 붙여 다시 부른다. 오타를 주면 CLI 가 유효한 게임 목록과
함께 거부하므로 (`profiles/` 와 대조) 잘못된 이름으로 새 DB가 생기지 않는다.

```bash
.venv/Scripts/qatc.exe slot init <컨텐츠> --game <게임> --types 편성
.venv/Scripts/qatc.exe slot set <컨텐츠> overview --status filled --value "<개괄 요약>"
```

**왜 개괄이 먼저인가.** `slot init` 은 **가산 전용**이다 — 재실행은 슬롯을
붙이기만 하고, 잘못 넣은 유형의 슬롯을 지우는 CLI 명령은 없다 (`qatc slot` 에는
`status` `init` `set` `add` 뿐이다). 설명을 듣기 전에 이름만 보고 `--types 던전`
을 추측하면 그 컨텐츠는 `던전.제한시간` 같은 항목을 영원히 미확인으로 달고 다니고,
커버리지 분모와 xlsx `미확인 항목` 시트에 그대로 남는다 (실측: `--types 던전` 으로
만든 뒤 `--types` 없이 다시 실행해도 슬롯 14개 그대로). 유형은 사용자의 설명에서
나오는 것이지 컨텐츠 이름에서 추측할 것이 아니다.

개괄 답변에 진입 경로·정원·재화가 이미 들어 있으면 **그 자리에서 전부 기록한다.**
컨텍스트 우선으로 시작하는 이득이 여기서 나온다.

## 2단계 — 인터뷰 루프

```bash
.venv/Scripts/qatc.exe slot status <컨텐츠> --json
```

`open` 배열에서 하나를 골라 `hint` 를 참고해 자연스럽게 묻는다. 힌트를 그대로
읽지 말고 이 게임·컨텐츠 맥락에 맞게 바꿔 묻는다.

답변을 받으면:

```bash
.venv/Scripts/qatc.exe slot set <컨텐츠> <키> --status filled --value "<사용자가 말한 내용>"
```

기록할 때마다 사용자에게 무엇이 기록됐고 몇 개가 남았는지 보여준다:

```
  ✓ constraints 기록됨
  [7/12 채움 · 남은 것: 재화, 실패 조건, 저장 시점]
```

### 사용자가 답을 정정하면

정정은 **오류가 아니라 인터뷰의 정상 동작이다** ("아, 그거 재화 안 써요").
같은 키에 새 상태로 `slot set` 을 다시 실행하면 된다.

```bash
.venv/Scripts/qatc.exe slot set <컨텐츠> cost --status na
```

그 계열의 TC를 이미 만들었다면 **지우지 않는다.** `tc list` 와 xlsx가 그 TC를
`근거 철회됨` 으로 표시하므로, 사용자에게 그 사실을 알리고 어떻게 할지 묻는다
(슬롯을 다시 채우면 표시가 사라진다).

## 3단계 — TC 생성

`open` 이 비면 (또는 사용자가 끝내자고 하면) 생성 대상을 확인한다:

```bash
.venv/Scripts/qatc.exe tc plan <컨텐츠> --json
```

`planned` 에 있는 계열만 작성한다. **`skipped` 에 있는 계열은 절대 만들지 않는다** —
만들어도 `tc add` 가 거부한다.

계열마다 한 번씩 실행한다:

```bash
.venv/Scripts/qatc.exe tc add <컨텐츠> --family "정상 경로" --origin interview --json - <<'JSON'
{"testcases": [
  {"title": "...", "precondition": "...",
   "steps": ["..."], "expected": ["..."],
   "rationale": "core_action 슬롯: '<사용자 진술 인용>'에서 도출"}
]}
JSON
```

`--origin` 을 정확히 고른다:

- `interview` — 사용자가 **말한 것**을 그대로 확인하는 TC
- `inferred` — 진술에서 **도출한 것** (예: "최대 4명"에서 "5명 넣으면 거부")

`rationale` 에는 **어느 슬롯의 어떤 문장에서 나왔는지** 적는다. TC를 의심할 때
근거를 되짚을 수 있어야 한다.

## 4단계 — 마무리

```bash
.venv/Scripts/qatc.exe tc list <컨텐츠>
.venv/Scripts/qatc.exe export <컨텐츠>
```

미확인 항목이 남아 있으면 사용자에게 알리고, 채우면 어떤 TC가 추가되는지 말해준다.

## 재개

세션이 끊겼거나 컨텍스트가 압축됐으면 `slot status` 한 번이면 복구된다.
채워진 항목을 건너뛰고 빈 항목부터 이어간다. 사용자에게 다시 물어보지 않는다.
