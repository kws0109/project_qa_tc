# 인터뷰 기반 TC 생성 — 구현 기록

**기간:** 2026-08-13 ~ 2026-08-14
**브랜치:** `feat/interview-tc` (`fa5de6c..dfd43fb`, 44 커밋)
**테스트:** 109 → **353 통과**
**계획서:** [plans/2026-08-14-interview-driven-tc.md](plans/2026-08-14-interview-driven-tc.md)
**설계:** [specs/2026-08-14-interview-driven-tc-design.md](specs/2026-08-14-interview-driven-tc-design.md)

이 문서는 **왜 그렇게 했는지**를 남긴다. 무엇을 만들었는지는 계획서와 코드가,
어떻게 바뀌었는지는 git 이력이 이미 기록한다. 여기 남는 것은 그 둘 어디에도
안 남는 판단 근거다.

구현은 태스크마다 새 서브에이전트를 붙이고, 매 태스크 후 리뷰(스펙 준수 + 품질)를
거쳐 수정 루프를 도는 방식으로 진행했다. 사용자 부재 중에는 아래 위임 규칙을 적용했다.

> 사용자가 취침 전 "수정·선택이 필요하면 추천안으로 자동 선택하고 근거를 기록"하도록 위임함.
> 적용 범위: 리뷰 지적 수정, 계획-루브릭 충돌 판단, 수정 루프 판정.
> 적용 제외: 설계 판단이 필요한 것 — 기록해 두고 사용자에게 보고한다.

## 1. 사용자 판단이 필요한 항목

### `--game` 이 `profiles/` 와 대조되지 않는다

`qatc slot init 테스트 --game 존재하지않는게임` → **rc=0, DB 생성**. 오타 하나면
`starrial.db` 가 조용히 생기고, 그 인터뷰는 `qatc knowledge` 어디에도 안 보인다.

설계 단계에서 `profiles/` 를 남긴 근거는 "게임 정체성이 거기 산다"였는데, 실제로는
아무것도 강제하지 않는다. 최종 리뷰가 결과 하나를 덧붙였다 — **`profiles/` 하위 시스템
전체(`qatc/profiles.py` + YAML 4개 + 런타임 의존성 `pyyaml`)의 유일한 소비자가
`qatc config` 의 목록 출력이다.**

| 안 | 내용 | 대가 |
|---|---|---|
| A | `--game` 을 프로파일 이름으로 제한 | 새 게임마다 YAML 을 먼저 만들어야 함. `pyyaml` 의존성이 정당해짐 |
| B | 현행 유지 | 오타가 조용히 지나감 |
| C | `profiles/` 와 `pyyaml` 을 함께 제거, `--game` 은 자유 문자열 | 게임 목록이라는 개념이 사라짐 |

**코드 결함이 아니라 설계 선택이라 자동 판단하지 않았다.** 어느 쪽이든 한 결정으로 묶인다.

## 2. 설계에서 지킨 것

핵심 불변식은 하나다 — **근거 없는 TC는 만들어지지 않는다.**

이 불변식을 프롬프트가 아니라 **코드**가 강제하도록 배치한 것이 이 브랜치의 전부라고
해도 된다. 구조는 두 관문이다.

- **로직 관문** (`qatc/knowledge/gate.py`) — 채워진 슬롯이 어떤 TC 계열을 정당화하는지
  `plan_families()` 가 계산한다.
- **경계 관문** (`qatc tc add`) — 정당화되지 않은 계열을 `validate_family()` 가
  막힌 슬롯 이름을 대며 거부한다.

`SlotStatus` 가 4상태(EMPTY / FILLED / UNKNOWN / NA)인 것도 여기 걸려 있다.
**"모른다"(UNKNOWN)와 "해당 없음"(NA)은 절대 TC의 근거가 되면 안 된다.** FILLED 만
근거가 된다. 이 구분이 무너지면 도구가 존재할 이유가 없어진다.

## 3. 최종 리뷰가 잡은 것 — 불변식이 실제로 뚫려 있었다

전체 브랜치 리뷰(뮤테이션 36종)가 **Critical 1 · Important 6 · Minor 20** 을 냈다.

```
qatc slot set 빈값 cost --status filled     ← --value 없음
→ ✓ cost = filled  (rc=0)
→ planned_families: ['재화 부족', ...]      ← 빈 문자열이 근거로 인정됨
```

게이트는 `status is FILLED` 만 보고 `value` 가 비었는지 아무도 안 봤다. **플래그 하나
빠뜨리는 것만으로 유일한 load-bearing 불변식이 무력화**되고, 결과물에서 근거 있는
TC 와 구별되지 않았다. 스펙 §8 이 "빈 값" 거부를 이미 요구했는데 구현도 테스트도 없었다.

이 구멍은 **세 번에 걸쳐** 닫혔다. 매번 "닫았다"고 판단한 다음 라운드에서 다시 열렸다.

| 라운드 | 통과하던 입력 | 왜 놓쳤나 |
|---|---|---|
| 1a | `--value` 없음 / `--value "  "` | 검사 자체가 없었음 |
| 1c | `--value $'​'` (제로폭·BOM·C0) | `str.strip()` 은 `isspace()` 인 문자만 지운다 |
| 1d | `--value $'ㅤ'` (한글 필러) | 블랙리스트가 `Cc/Cf/Zs/Zl/Zp` 뿐 — 필러는 `Lo` |

**U+3164 HANGUL FILLER 는 한국 게임에서 빈 이름·간격용으로 흔히 쓰는 바로 그 문자다.**
한국어 게임 QA 도구에서 이건 예외적 입력이 아니다. 최종 게이트 리뷰어가 Minor 로
분류한 것을 실측 후 차단 항목으로 올렸다 — **최후 방어선의 구멍은 발생 확률이 아니라
뚫리는지 여부로 등급을 매겨야 한다.**

### 산출물이 스스로를 부정하던 문제 (I1)

근거를 철회해도 이미 만든 TC 가 남아, 같은 출력이 "TC 가 있다"와 "TC 가 없다"를
동시에 말했다. 어느 태스크도 소유하지 않은 이음새였다 — Task 4 는 게이트, Task 7 은
`tc add`, Task 9 는 xlsx 를 맡았고 "TC 생성 이후 슬롯 상태가 바뀌면" 은 아무도 안 봤다.

검토자가 제시한 3안 중 **1안(표시하되 삭제하지 않는다)** 을 택했다. 근거 — 인터뷰에서
답 정정은 정상 행동이고, **사용자 데이터는 절대 지우지 않는다.** 2안(`slot set` 경고)은
스크롤백으로 사라지지만 모순은 xlsx 에 남는다. 산출물이 문제이므로 산출물에서 고친다.

### 말없이 TC 를 지우던 문제 (BL2)

```
1차 → ✓ [정상 경로] TC 2건 저장   → tc list: A, B
2차 → ✓ [정상 경로] TC 1건 저장   → tc list: C 만 남음   (A·B 삭제, 안내 없음)
```

`replace_generated` 가 `(added, kept)` 만 돌려줘 CLI 가 삭제 수를 알 방법이 없었다.

**`--replace` 게이트 대신 "소리 내기"를 택했다.** 근거 — `replace_generated` 의 존재
이유가 "한 계열의 생성분 갈아끼우기"이고 `generated_hash` 는 그 교체가 사람 수정본을
건드리지 않게 하려고 있다. 즉 교체가 의도된 의미론이고, 스펙 헤드라인 문장
("기존 TC를 지우지 않는다") 쪽이 자기 하위 항목과 어긋난 부정확한 서술이었다.
이 명령의 1차 독자가 모델이라 **출력에 찍히는 경고가 곧 신호**다. 스펙 문장도 함께 고쳤다.

## 4. 뮤테이션 테스트를 리뷰 방법으로 고정한 이유

Task 2에서 처음 드러났다. dedup 테스트 2개가 "먼저 조립된 것이 이긴다"를 검증한다고
이름 붙어 있었는데, 병합 규칙을 **last-wins 로 뒤집어도 그대로 통과**했다.

최종적으로 **"코드는 옳은데 테스트가 이름값을 못 하는"** 결함이 **아홉 번** 나왔다.
전부 코드를 읽어서는 안 잡히고 뮤테이션으로만 잡혔다.

가장 뾰족한 두 사례:

- **Task 7** — 검토자가 `gate.py` 를 **건드리지 않고** `cmd_tc_add` 의 `except ValueError`
  안에 UNKNOWN/NA 우회를 심었는데 207개가 전부 통과했다. 설계가 존재하는 이유
  그 자체가 경계에서 무방비였다.
- **9번째** — `test_add_rejects_missing_required_field` 는 필수 필드 검증을 **통째로
  지워도** 통과했다. 검증이 없으면 `KeyError: 'steps'` 가 나고, 그 예외 메시지가
  테스트의 두 단언(`rc == 1`, `"steps" in out`)을 **둘 다** 만족시켰다.
  이 테스트는 **태스크 리뷰 11번과 최종 리뷰 1차를 전부 통과**했다.

같은 모양이 반복된다 — **이웃 줄의 부분문자열이라 공짜인 단언.**
`assert "중단" in out` 이 바로 위의 `assert "중단됨" in out` 에 포함돼 무의미했고,
`assert "교체" not in first` 가 바로 위의 `assert "⚠" not in first` 와 같은 `_p()`
호출에서 나와 무의미했다.

**교훈:** 테스트 이름이 주장하는 것과 테스트가 실제로 검증하는 것은 다르다. 구현을
깨뜨려 보기 전까지는 어느 쪽인지 알 수 없다.

## 5. 에이전트 보고를 액면가로 받지 않은 사례

두 번, 자신 있게 서술된 주장이 **거짓**이었고 코드를 직접 실행해서 반증했다.

**(1) "게이트가 `tc add` 에서 미등록 계열을 이미 거부한다"** — 1a 보고서의 주장.
CLI 를 우회해 오타 계열 슬롯을 주입해 보니:

```
FAMILY_META 에 등록됨? : False
plan_families ->      : ['중단됨']
validate_family ->    : PASSED 중단됨 TCKind.HAPPY_PATH Priority.MEDIUM
```

미등록 계열은 거부되지 않고 **조용히 정상 경로 / Medium 으로 배정**된다.
오타가 실패하는 대신 산출물에서 가장 신뢰도가 높은 범주의 TC 를 위조하고, 그 오타는
xlsx 어디에도 안 보인다.

*행동*(CLI 검증 + 폴백 고정 테스트)은 검토자 판정을 충족했으므로 되돌리지 않고,
잔여 구멍만 **게이트 계층**에 방어를 넣어 닫았다 — 구현자가 우려한 store→gate 계층
역전이 생기지 않고, CLI 밖 모든 호출자를 한 번에 막는다. 폴백은 아예 제거했다.

**(2) "`config.json` 이 `[]`·`42`·`"x"` 면 조용히 기본값으로 되돌아간다"** — 분석
에이전트의 HIGH 등급 지적. 실측하니 `rc=1` 에 파일 경로와 복구 방법을 알리는 정상
동작이었다. `isinstance(raw, dict)` 가드가 실재한다. 실제 결함은 **동작이 아니라
그 분기를 덮는 테스트가 없다는 것**이었다. 심각도가 과장된 지적이라, 수정 지시에
"동작은 옳으니 코드를 고치지 말고 테스트만 붙여라"를 명시했다.

### 반대로, 구현자가 옳았던 경우 — 네 번

지시에 반대하고 증거를 낸 구현자는 **네 번 다 옳았다.**

- **Task 6** — 계획서의 의존 방향이 거꾸로였다 (`main()` 의 `SystemExit` 처리를
  Task 8에 배치했는데 Task 6 테스트가 그걸 필요로 함). 추측 없이 멈춘 것이 옳았다.
- **Task 4** — 내가 지정한 멤버십 테스트가 해당 뮤테이션을 못 죽인다는 것을 실증하고
  (dict 키 멤버십은 쓰기 순서 불변) 실제로 죽는 테스트를 따로 만들었다. **내 지시가
  부정확했다.**
- **1a** — `cmd_knowledge` 는 "게임 DB 없음" 이라 컨텐츠 문구를 공유하면
  `컨텐츠 'starrail'가 없습니다` 라는 **거짓 문장**이 된다며 별도 문구를 썼다.
- **1e** — 내가 "중복 파라미터"라고 지목한 `[table-locked]` 가 실은 부분문자열
  매칭 대 등가 비교를 가르는 **유일한 검출자**임을 뮤테이션으로 보이고 건너뛰었다.

## 6. 실제로 사용자를 죽였을 버그

전부 전체 테스트 스위트를 통과하고 있었다.

### `_p()` 폴백이 무동작

```python
except UnicodeEncodeError:
    print(msg.encode("utf-8", "replace").decode("utf-8", "replace"))  # 동일 문자열
```

폴백이 **똑같은 문자열**을 다시 출력해 같은 `UnicodeEncodeError` 가 미처리로 재발한다.
`✓` 는 cp949(한국어 Windows 기본)에서 인코딩 불가라, `slot set` / `tc add` / `export`
의 확인 줄이 실제 콘솔에서 전부 크래시한다.

**작업은 성공한 뒤 성공 메시지가 프로세스를 죽인다.** 사용자에게는 실패로 보인다.
**pytest 가 UTF-8 로 캡처하기 때문에** 전 스위트가 못 잡았다.

### xlsx 제어문자 미소독

구 `export/excel.py` 는 openpyxl 소독이 없어 `\x03` 하나에 export 전체가
`IllegalCharacterError` 로 죽었다. 새 `tc_excel.py` 는 **모든 셀 값**이 `clean_cell` 을
통과한다.

## 7. 아직 열려 있는 것

전부 의도적으로 남긴 것이고, 근거가 있다.

| 항목 | 판정 근거 |
|---|---|
| `--game` 미검증 | **사용자 판단 대기** (1절) |
| `tc add --origin user` 비멱등 — 같은 명령 3회에 동일 TC 3개 | `replace_generated` 가 USER 를 무조건 보존하는 것은 "사람이 손댄 것을 재생성이 덮지 않는다"는 설계 의도 그대로다. 해시 기준 중복 제거로 바꾸면 그 의도와 충돌할 수 있고, "USER TC 의 동일성이 무엇인가"는 설계 질문이다 |
| `testcases.slot_keys` · `contents.game` 이 쓰기 전용 | 읽는 코드가 0 이다. 역추적 기능을 만들 때 그 기능의 테스트로 함께 고정하는 편이 낫다 |
| `KnowledgeStore.init_content` 가 이름을 검증하지 않음 | 불변식은 양 계층에, 입력 위생은 CLI 경계에 두는 분리를 따랐다. 직접 store 호출자만 해당 |
| `is_blank` 가 블랙리스트 | 화이트리스트로 뒤집어도 한글 필러(`Lo`)·점자 공백(`So`) 예외 목록이 그대로 필요하다. 차이는 미지 문자의 기본값뿐이고, 거기서는 기본-허용이 안전하다 — 기본-거부는 정당한 답변을 조용히 버리고 인터뷰를 세운다. 안 잡는 것을 docstring 이 명시한다 |

## 8. 향후 작업 시 주의

- **pytest 가 UTF-8 로 캡처하므로 콘솔 인코딩 버그는 전 스위트를 통과한다.** 한글
  Windows 콘솔 동작은 테스트가 아니라 실제 실행으로 확인해야 한다.
- **pytest capture manager 는 fixture setup 과 test call 사이에 `sys.stdout` 을
  재설치한다.** fixture 안에서 monkeypatch 하면 조용히 버려진다.
- **`argparse` 의 `SystemExit(2)` 는 `parse_args` 가 try 밖이라 `main()` 의 문자열
  가드를 안 탄다.** int 코드는 계속 전파돼야 한다.
- **`--family` 에 argparse `choices` 를 붙이지 말 것.** argparse 가 rc=2 로 죽으면서
  막힌 슬롯 이름을 알려주는 `validate_family` 의 메시지를 버린다.
- **`TCOrigin` 의 기존 문자열 값은 고정이다.** 엑셀 색 매핑과 기존 DB 가 의존한다.
- **`.gitignore` 의 `/knowledge/` 앵커는 필수다.** 앵커가 없으면 `qatc/knowledge/`
  (살아있는 소스 패키지)까지 매칭돼 새 파일이 조용히 추적에서 빠진다.
- **`str.strip()` 을 "빈 값" 판정에 쓰지 말 것.** `isspace()` 인 문자만 지운다 —
  제로폭·BOM·한글 필러가 전부 통과한다. `qatc/knowledge/models.py` 의 `is_blank` 를 쓸 것.
- **뮤테이션으로 검증하지 않은 테스트는 완료가 아니다.** 이 브랜치에서 아홉 번 증명됐다.

녹화 파이프라인 전체 (52 파일, 약 10,800줄). 근거는 측정값이다 — 실측 세션에서 검출된

이력에서 복원할 수 있다.

## 10. 프로세스에서 내가 틀린 것

- **`git add -A` 로 구현자의 미완성 작업을 계획 수정 커밋에 쓸어담았다.**
  soft reset 으로 분리해 계획만 커밋하고 작업은 워킹트리에 보존했다.
- **백그라운드 자식이 살아 있는 채로 다음 라운드를 디스패치했다.** 최종 게이트
  리뷰어가 분석 에이전트를 남긴 채 종료했는데 그 위에 수정 라운드를 붙였다. 그 라운드가
  같은 파일에 뮤테이션을 걸고 되돌리는 동안 분석 에이전트가 그것을 "외부 프로세스가
  파일을 고친다"로 관측했다. 결과는 유효했지만(그 에이전트가 `git archive` 사본으로
  작업했다) **동시 디스패치 전에 백그라운드 자식을 확인했어야 한다.**
- **구현자 두 명이 뮤테이션 복원에 `git checkout` 을 써서 커밋 안 된 작업을 날렸다.**
  이후 지시에 "에디터로 원문을 다시 쓸 것, `git checkout`/`stash`/`reset` 금지"를
  명시했다. 한 명은 빈 문자열로 치환하는 뮤테이션을 썼다가 `str.count("")` 가 문자열
  길이를 반환하는 바람에 복원에 실패했다 — **빈 문자열이 아닌 다른 값으로 치환할 것.**
